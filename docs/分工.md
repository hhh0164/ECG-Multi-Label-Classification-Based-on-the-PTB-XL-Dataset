# PTB-XL ECG 多标签分类项目三人分工方案

> 适用任务：基于 PTB-XL v1.0.3（100Hz）12 导联 ECG 的五类诊断超类多标签分类  
> 标签固定顺序：`["NORM", "MI", "STTC", "CD", "HYP"]`  
> 提交材料：Word 实验报告 + 汇报 PPT + 完整代码与 README  
> 评分构成：当堂汇报 30 分 + 代码 40 分 + Word 报告 30 分

---

## 1. 分工总原则

1. **主责模块 + 交叉审查**：每人主责一个模块，但关键产物必须由另外两人审查。
2. **接口先行**：先约定标签顺序、数据划分文件、预测结果 CSV 格式，再并行开发。
3. **测试集纪律**：测试集只用于最终评估；调参、早停、阈值选择只能用验证集。
4. **数字一致性**：报告、PPT、代码输出中的指标必须来自同一份评估结果文件。
5. **可复现优先**：固定随机种子，README 写清环境、数据路径、训练和测试命令。
6. **不提交原始数据**：原始 ECG 数据不进仓库、不进压缩包。

## 2. 角色与职责

### 成员 A：数据与标签负责人

**核心目标**：保证标签映射正确、数据划分规范、无患者级泄漏、预处理只使用训练集统计量。

**具体任务**

- 下载并整理 PTB-XL v1.0.3：
  - `ptbxl_database.csv`
  - `scp_statements.csv`
  - `records100/` 波形文件
- 实现诊断代码映射：
  - 读取 `scp_codes` 字段；
  - 只保留 `scp_statements.csv` 中 `diagnostic == 1` 的 SCP 代码；
  - 映射到 `diagnostic_class`，得到 `NORM/MI/STTC/CD/HYP` 五维 0/1 标签；
  - 处理无法映射或非 diagnostic 代码，并在报告中说明规则。
- 标签统计：
  - 记录数、患者数；
  - 每类阳性样本数与比例；
  - 多标签样本数量；
  - 标签共现矩阵与共现分析。
- 数据划分：
  - 优先官方 fold：1–8 训练、9 验证、10 测试；
  - 检查同一 `patient_id` 不跨训练/验证/测试；
  - 输出统一的 `split.csv` 或 `split.json`。
- 波形读取与预处理：
  - 使用 `wfdb` 读取 `records100`；
  - 说明采样率 100Hz、时长 10s、输入张量形状；
  - 归一化参数只由训练集拟合；
  - 实现 PyTorch `Dataset` 和 `DataLoader`。
- 撰写报告“数据集介绍、标签构建、数据统计、预处理与划分”章节初稿。

**交付物**

- `label_mapping.py`：标签映射脚本
- `data_stats.csv` / `label_cooccurrence.csv`：标签统计与共现结果
- `split.csv`：训练/验证/测试划分文件
- `dataset.py`：数据读取与预处理代码
- 数据章节初稿与相关图表
- 标签映射抽查记录（至少抽查 10 条记录）

**审查责任**

- 审查 B 的模型输入是否与 Dataset 输出形状一致；
- 审查 C 的评估脚本是否使用了正确的测试集划分。

---

### 成员 B：模型与训练负责人

**核心目标**：实现至少一种深度模型，完成主实验和一组对比实验，保证训练过程可复现且不使用测试集。

**具体任务**

- 实现至少一种深度模型，建议：
  - 1D CNN 基线；
  - 或 ResNet1D / InceptionTime / 轻量 Transformer。
- 多标签损失函数：
  - 使用 `BCEWithLogitsLoss`；
  - 可选 `pos_weight`，权重只能由训练集统计得到。
- 训练设置：
  - 优化器 Adam/AdamW；
  - 学习率、batch size、epoch 数；
  - 早停依据验证集 macro-AUROC 或验证损失；
  - 固定随机种子。
- 对比实验，至少一组：
  - 无类别权重 vs 有类别权重；
  - 或基础 CNN vs 改进结构；
  - 或有无数据增强；
  - 或不同学习率/损失配置。
- 保存训练产物：
  - 模型权重；
  - 验证集与测试集预测概率 CSV；
  - 训练日志与损失曲线。
- 撰写报告“模型结构、损失函数、训练设置、对比实验”章节初稿。

**交付物**

- `models.py`：模型定义
- `train.py`：训练脚本
- `configs/`：实验配置文件
- `checkpoints/`：模型权重或重训说明
- `predictions_val.csv`、`predictions_test.csv`：预测概率
- 训练日志与损失曲线图
- 方法章节初稿

**审查责任**

- 审查 A 的标签映射是否与模型输出维度一致；
- 审查 C 的评估是否使用了正确的预测文件和标签顺序。

---

### 成员 C：评估、错误分析与文档负责人

**核心目标**：实现完整多标签评价指标，完成测试集最终评估、错误案例分析和文档整合。

**具体任务**

- 实现评价指标：
  - 每类 AUROC、AUPRC、Precision、Recall、F1-score；
  - macro-average 与 micro-average；
  - 每类 2×2 混淆矩阵或多标签阈值化后的混淆矩阵，并说明含义。
- 阈值选择：
  - 默认 0.5；
  - 若调阈值，只能使用验证集，按每类或全局 F1 最优选择；
  - 固定阈值后用于测试集，报告中说明方法。
- 测试集最终评估：
  - 只评估一次；
  - 输出每类指标表、macro/micro 汇总表；
  - 保存评估结果为 CSV/JSON，供报告和 PPT 使用。
- 错误分析：
  - 至少挑选 5 个错误预测案例；
  - 展示波形、真实标签、预测概率、预测标签；
  - 讨论类别不平衡、标签噪声、超类粗粒度、共现标签影响和模型局限性。
- 文档整合：
  - 整合 Word 实验报告；
  - 制作 8–12 页汇报 PPT；
  - 编写 README 和 `requirements.txt`；
  - 检查压缩包命名与提交清单。

**交付物**

- `evaluate.py`：评估脚本
- `metrics_test.csv`、`metrics_summary.json`：最终指标
- `confusion_matrices/`：混淆矩阵图
- `error_cases/`：至少 5 个错误案例材料
- Word 报告整合版
- 汇报 PPT
- `README.md`、`requirements.txt`
- 最终压缩包

**审查责任**

- 审查 A 的标签统计与报告数字是否一致；
- 审查 B 的预测 CSV 格式、标签顺序和测试集使用是否规范。

## 3. 统一接口约定

### 3.1 标签顺序

所有代码、报告、PPT 统一使用：

```python
LABELS = ["NORM", "MI", "STTC", "CD", "HYP"]
```

不得在不同文件中改变顺序。

### 3.2 数据划分文件格式

`split.csv` 至少包含：

```csv
ecg_id,patient_id,strat_fold,split
1,1,1,train
2,1,1,train
...
```

其中 `split` 取值为 `train/val/test`。B 和 C 必须使用同一份 `split.csv`。

### 3.3 预测结果 CSV 格式

`predictions_val.csv` 和 `predictions_test.csv` 至少包含：

```csv
ecg_id,patient_id,fold,
y_true_NORM,y_true_MI,y_true_STTC,y_true_CD,y_true_HYP,
prob_NORM,prob_MI,prob_STTC,prob_CD,prob_HYP
```

如已确定阈值，可增加：

```csv
pred_NORM,pred_MI,pred_STTC,pred_CD,pred_HYP
```

### 3.4 评估输出格式

`metrics_test.csv` 建议包含：

```csv
label,auroc,auprc,precision,recall,f1,support
NORM,...
MI,...
STTC,...
CD,...
HYP,...
macro,...
micro,...
```

### 3.5 代码仓库结构建议

```text
project/
├── README.md
├── requirements.txt
├── configs/
│   └── baseline.yaml
├── data/
│   ├── label_mapping.py
│   ├── dataset.py
│   └── split.csv
├── models/
│   └── models.py
├── train.py
├── evaluate.py
├── checkpoints/
├── outputs/
│   ├── predictions_val.csv
│   ├── predictions_test.csv
│   ├── metrics_test.csv
│   └── metrics_summary.json
└── figures/
```

原始数据目录不进入仓库，README 中说明数据路径配置方式。

## 4. 时间安排

### 第 1 周：打通端到端小样本 pipeline

| 成员 | 任务 |
|---|---|
| A | 完成数据下载、标签映射、标签统计、官方 fold 划分、患者不跨集合检查、Dataset 实现 |
| B | 搭建 1D CNN 基线模型和训练脚本，使用小样本跑通训练 |
| C | 实现 AUROC/AUPRC/P/R/F1 和 macro/micro 指标函数，搭建报告框架 |

**周节点检查**：三人共同用 100–200 条小样本跑通“读取波形 → 标签映射 → 训练 → 预测 CSV → 评估指标”全链路。

### 第 2 周：主实验与对比实验

| 成员 | 任务 |
|---|---|
| A | 补充标签分布图、共现矩阵图，完成数据章节初稿 |
| B | 完成主模型全量训练和至少一组对比实验，保存验证集/测试集预测概率 |
| C | 用验证集确定阈值，完成评估脚本，准备结果表和混淆矩阵模板 |

**周节点检查**：B 提交 `predictions_val.csv`，C 能独立复现验证集指标；A 检查划分无患者泄漏。

### 第 3 周：最终评估与文档整合

| 成员 | 任务 |
|---|---|
| A | 审查标签映射和统计数字，完成数据章节定稿 |
| B | 审查模型和训练设置描述，提供方法章节定稿和对比实验表 |
| C | 完成测试集最终评估、5 个错误案例、报告整合、PPT 和 README |

**周节点检查**：报告数字、PPT 数字、`metrics_test.csv` 三方一致。

### 最后 2–3 天：复现检查与汇报演练

- 从干净环境按 README 重跑评估脚本；
- 检查压缩包命名：`班级_学号_姓名_PTBXL_ECG多标签分类.zip`；

## 7. 风险与避坑清单

| 风险 | 后果 | 责任人 | 规避措施 |
|---|---|---|---|
| 同一患者跨训练/验证/测试 | 数据泄漏，严重扣分 | A | 按 `patient_id` 检查三集合交集为空 |
| 用全量数据拟合归一化参数 | 统计泄漏 | A | 只用训练集计算均值和标准差 |
| 用测试集早停或调参 | 实验不规范 | B | 早停只看验证集 |
| 用测试集调阈值 | 评估不可信 | C | 阈值只在验证集选择 |
| 只报 Accuracy | 指标不完整 | C | 必须报 AUROC/AUPRC/P/R/F1 和 macro/micro |
| 标签顺序不一致 | 结果错位 | 三人 | 统一 `LABELS` 常量 |
| 报告数字与代码不一致 | 视为不严谨或虚构 | 三人 | 统一从 `metrics_test.csv` 取数 |
| 混淆矩阵含义不清 | 结果展示扣分 | C | 每类 2×2 矩阵并说明多标签阈值化规则 |
| 原始数据被打包 | 违反要求 | C | 提交前检查压缩包 |
| README 无法复现 | 可复现性扣分 | B/C | 干净环境按 README 重跑 |

## 8. 每周同步机制建议

- **每周一次 30 分钟组会**：每人 5 分钟进度 + 5 分钟问题；
- **每日轻量同步**：在群内更新“昨天完成 / 今天计划 / 阻塞点”；
- **代码合并前审查**：至少一名其他成员 review；
- **结果文件唯一来源**：所有指标以 `outputs/metrics_test.csv` 和 `metrics_summary.json` 为准；
- **文档版本管理**：报告和 PPT 文件名带日期或版本号，避免覆盖。
